Deep research, running locally.

A small model can search, inspect, and explain before it answers.

Jan-nano JQ4 ↗Technical report ↗

Deep research is not a bigger prompt. It is a small local model, a few bounded tools, and a short loop that knows when to look again. Reckoning lets the model search for evidence, choose a source, read a useful window, and then write an answer from what it found.

The loop

question
  -> web_search
  -> choose a source
  -> scrape a bounded window
  -> answer with evidence

Search returns titles, snippets, and URLs. Scrape caches a page and returns only the next useful window, so a CPU model does not prefill an entire web page.

A real question

Does Reckoning support JQ4?
If so, how many bits are used for the quantized values, and how are the scale factors stored?

What happened

[tool] web_search {"query":"Does Reckoning support JQ4?"}

[results]
1. reckoning/reckoning-nanocode/run-server-qwen3-4b-jq4-turboquant.sh
2. reckoning/reckoning-nanocode/run-server-dead-to-rights-qwen3-0.6b-jq4.sh
3. granite-4.1-3b-llmon-preview-JQ4

[tool] scrape {
  "url": "https://github.com/edwardcapriolo/reckoning/blob/main/reckoning-nanocode/run-server-qwen3-4b-jq4-turboquant.sh",
  "offset": 0,
  "limit": 1000
}

[answer]
Reckoning supports JQ4. Quantized values use 4 bits and scale factors are stored as 32-bit floating-point values.

It started uncertain

Jan-nano did not pretend to know what JQ4 was. It recognized that the question required research and chose web_search before answering.

It found signal and noise

DuckDuckGo returned Reckoning scripts, a JQ4 model on Hugging Face, a dictionary result, and an unrelated forum page. The model had to decide which result belonged to the question instead of treating every hit as evidence.

It narrowed the context

It selected a Reckoning GitHub result and called scrape with offset=0 and limit=1000. The fetcher reported a 12,216-character cached page and returned only the first window. That is the practical part of the loop: the model did not prefill the whole page.

It found the useful answer, with a visible weakness

The final answer got the central point: JQ4 uses 4-bit quantized values and floating-point scale data. Its attribution was weaker than the answer because it relied on a launch script rather than the authoritative JQ4 format documentation. That is exactly the kind of trace a research tool should make visible.

The interesting result is the path: uncertainty, search, noisy evidence, source selection, bounded retrieval, and synthesis. The full captured run ↗ shows every step.
