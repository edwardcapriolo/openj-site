Deep research, running locally.

A small model can search, inspect, and explain before it answers.

Jan-nano JQ4 ↗Technical report ↗

Deep research is not a bigger prompt. It is a small local model, a few bounded tools, and a short loop that knows when to look again. Reckoning lets the model search for evidence, choose a source, read a useful window, and then write an answer from what it found.

The loop

question
  -> web_search
  -> choose a source
  -> scrape a bounded window
  -> answer with evidence

Search returns titles, snippets, and URLs. Scrape caches a page and returns only the next useful window, so a CPU model does not prefill an entire web page.

A real question

Does Reckoning support JQ4?
If so, how many bits are used for the quantized values, and how are the scale factors stored?

What happened

01 / The question

Does Reckoning support JQ4?
If so, how many bits are used for the quantized values,
and how are the scale factors stored?

The model starts by admitting uncertainty:

“I don't have prior knowledge about Reckoning or JQ4,
so I should start by performing a web search...”

02 / The first tool call

<tool_call>
{"name": "web_search", "arguments": {"query": "Does Reckoning support JQ4?"}}
</tool_call>

This is a real DuckDuckGo request, not a canned result.

03 / Search results

result-1  reckoning/reckoning-nanocode/run-server-qwen3-4b-jq4-turboquant.sh
result-2  reckoning/reckoning-nanocode/run-server-dead-to-rights-qwen3-0.6b-jq4.sh
result-3  granite-4.1-3b-llmon-preview-JQ4
result-4  Merriam-Webster: RECKONING
result-5  unrelated Return of Reckoning forum

The search is noisy. Two project scripts and a model card look relevant; the dictionary and game forum do not.

04 / The model chooses a source

“The first result is a GitHub link to a script named
'run-server-qwen3-4b-jq4-turboquant.sh'... The URL is from the
Reckoning repository, so that's a relevant source.”

It makes a reasonable relevance decision, but not the perfect source decision. The important point is that the choice is visible.

05 / The second tool call

<tool_call>
{"name": "scrape", "arguments": {
  "url": "https://github.com/edwardcapriolo/reckoning/blob/main/reckoning-nanocode/run-server-qwen3-4b-jq4-turboquant.sh",
  "offset": 0,
  "limit": 1000
}}
</tool_call>

The page was cached at 12,216 characters, but only the first 1,000-character window was sent back to the model.

06 / The answer

“Reckoning supports JQ4 (4-bit quantization). Quantized values
use 4 bits, and scale factors are stored as 32-bit floating-point
numbers.”

The answer got the central fact. Its attribution was weaker than it should have been because it scraped a launch script instead of the JQ4 format documentation. That weakness is part of the result, not something hidden from the reader.
